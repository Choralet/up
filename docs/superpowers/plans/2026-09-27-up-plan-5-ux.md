### Task 1: Phase 1: slips and bugs

Tests then fixes:
1. Warm-up ticks and "Train Anyway" survive switching tabs and a reload (saved in `progress.day` for today's date; new day starts fresh). Changing the schedule clears the pick.
2. Log Set: a second tap within `logTuning.doubleTapMs` (default 600 ms, tests set 0) is ignored; one test keeps 600 and double-clicks → 1 set. The newest set chip gets class `new` (brief highlight).
3. Done during a hold → **Log It**: uses the same `record()` path; if that set reaches the goal the level-up sheet opens (screen stays), otherwise the screen closes.
4. Roadmap **Done** rows: check icon + normal text colour (not the grey of Locked).
5. Roadmap sheet **Needs** = requirements of the item's **first** step (external prerequisites), shown with ✓; the item's own steps only appear under Steps.
6. Import count: reproduce with a fixture (12 completed ids in a file), find the cause, fix and pin with a test (or document if the file itself was inconsistent).

### Task 2: Phase 2: a complete workout

1. Today row text: before any set `3 × 10`; after sets `2 of 3 sets · best 5`; a grey ✓ when the set count is logged, a green ✓ when the goal is met (accessible names "Sets done", "Goal reached").
2. Workout blocks (engine `buildWorkout`): `main` (unchanged) + `extra: { node, role: 'volume' | 'core' }[]`:
   - **volume**: for each main strength focus, its completed strength parent in the same branch (e.g. Knee push-up when Push-up is focus); none for the branch root.
   - **core**: on Push and Pull days, the core branch focus (Legs + Core days already train core).
   Today shows them under "Also today". "Workout complete" = every main/skill/extra exercise has its set count logged today.
3. **Finish Workout** button (bottom of Today, shown once any set is logged today) → sheet "Workout summary": each exercise with sets and best, "New best" markers (today's best > best before today), next training day, **Done**.
4. Rep stepper starts from the **last session's** first set (a previous date), else the last set today, else the goal; label "last session N". "last time" wording removed.

### Task 3: Phase 3: hold timer

1. Start → 3-second countdown (3, 2, 1, visible and announced), then timing starts from zero.
2. While running, a full-screen overlay (ring + time, "Tap Anywhere to Stop") is the stop button.
3. At the goal: a soft tone (Web Audio, ~0.25 s, low volume) if `settings.holdSound`; Settings has a "Sound at Hold Goal" switch. Tone code is injectable for tests (`holdTone.play`).
4. After stop: ring resets, text "Logged 0:23". The "A hold is running" sheet shows live time.

### Task 4: Phase 4a: Skills tab, vocabulary, names, Roadmap

1. Skills tab = **Now | Roadmap** (remember the choice). **Library removed.**
   - **Now**: "Training (n of 2)" with current step, Log This, Stop; **Ready to Start**: every skill chain not active whose next step is ready, named by its Roadmap item when it has one (else chain name), with **Start** (or **Replace…** choice when both slots are full); empty text points to the Roadmap for locked skills.
2. Vocabulary everywhere: tree node sheet and accessible names use Locked/Ready/Training/Done (aria words lowercase: `locked`, `ready`, `training`, `done`, plus `, skill`); level-up choices say "New" / "Ready".
3. Names: node "Hollow hold" → "Hollow body hold"; Roadmap item names use the app names ("False-grip pull-up", "90-degree hold", "Single-leg Romanian deadlift", "Straddle planche"); the video's own chapter title appears on the sheet as "In the video: …".
4. One line per screen saying what it is for (Tree, Skills Now, Roadmap).
5. Roadmap: "Ready Now" section at the top; each year collapsible (first unfinished year open); neutral SVG icons (lock, check, dot) instead of emoji.
6. At the 2-skill limit the Roadmap sheet offers **Replace <skill>** for each active skill.
7. Log screen of a skill step without a GIF but with a Roadmap item: **Watch in Video** as its How-to.
